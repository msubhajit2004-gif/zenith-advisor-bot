## AI Shopping Concierge — Build Plan

A judge-ready agentic shopping assistant that runs the full Browse → Search → Filter → Compare → Purchase loop in one fluid conversation. Built on TanStack Start with Lovable Cloud + Lovable AI.

### Core experience

A single chat-first page. The user types (or speaks) what they want, and the Concierge:

1. **Triages intent** — if vague, asks 2–3 sharp follow-up questions before showing anything.
2. **Recommends 2–3 products** with a personalized "Why this fits you" tied to the user's own answers.
3. **Explains trade-offs** explicitly when prices/specs differ ("Product A costs $40 more for 2x battery life").
4. **Closes the loop** — "Add to cart now, or compare with a premium option?"

### Pages

- `/` — Concierge chat (main demo surface): chat thread on the left, live "Recommendations" panel on the right with product cards, a Compare drawer, and a Cart sheet.
- `/cart` — Simulated checkout summary with a "Place order" confirmation (no real payment).

### Key features

**Catalog (AI-generated, multi-category)**
- On first run, a server function uses Lovable AI to generate ~40 realistic products across 6 categories (electronics, fitness, home, kitchen, audio, outdoor). Each product: name, category, price, key specs, pros/cons, short description, image URL placeholder.
- Stored in Lovable Cloud (Postgres). Embeddings generated per product and stored for semantic retrieval.
- A "Regenerate catalog" admin button on `/` (small, corner) lets judges reseed live.

**Agentic chat**
- Server function `/api/chat` streams responses from Lovable AI Gateway (`google/gemini-3-flash-preview`) using the system prompt provided by the user, verbatim, with the four phases enforced.
- Tool calling: the model has access to `search_catalog(query, filters)`, `get_product(id)`, `compare_products(ids)`, `add_to_cart(id, qty)`. The Concierge decides when to call these — this is the true "agentic" behavior judges look for.
- RAG: `search_catalog` runs vector similarity over the catalog embeddings and returns top-k with full specs injected into tool result.
- Conversation history fully preserved per session.

**Recommendation rendering**
- Tool calls return structured product data; the UI renders rich product cards inline in the chat AND mirrors them in the right-hand panel.
- Each card has: image, name, price, 3 key specs, "Why this fits you" blurb (from the model), Add to Cart, Compare checkbox.

**Side-by-side compare view**
- Up to 3 products in a slide-over drawer. Spec rows aligned, price diff highlighted, trade-off summary generated by a focused server function call ("explain the trade-offs between these in 2 sentences").

**Cart + checkout simulation**
- Persistent cart in Cloud, tied to anonymous session id (cookie). Cart sheet from header. `/cart` shows line items, subtotal, and a "Complete purchase (demo)" button that shows a success state.

**Voice input**
- Mic button in the chat composer. Uses ElevenLabs realtime STT (`scribe_v2_realtime` via `@elevenlabs/react`) with a server-issued single-use token. Live partial transcript shows in the input box; committed transcript auto-sends or stays editable (toggle).
- Requires `ELEVENLABS_API_KEY` secret — we'll prompt for it after plan approval.

**Thought-process toggle (judge bait)**
- Header switch: "Show reasoning". When on, every assistant message expands a collapsible "Concierge reasoning" panel showing:
  - Detected intent + extracted constraints
  - Which tools were called and with what arguments
  - Why each recommended product was chosen vs. rejected alternatives
- Implemented by having the model emit a structured `reasoning` field via a tool call alongside its user-facing reply, plus the raw tool-call trace from the server.

### Visual design

- Clean, premium, advisor-feel: warm neutral background, deep navy primary, single accent (amber) for CTAs and trade-off highlights. Generous whitespace, serif display font for headings to signal "concierge / consultant," sans for body.
- Streaming text with a soft cursor. Product cards have subtle elevation and hover lift. Compare drawer uses sticky header with diff highlights.

### Technical notes

- Stack: TanStack Start, Lovable Cloud (Postgres + pgvector), Lovable AI Gateway, ElevenLabs realtime STT, shadcn/ui.
- Tables: `products`, `product_embeddings` (vector), `chat_sessions`, `chat_messages` (with `tool_calls` jsonb + `reasoning` jsonb), `carts`, `cart_items`.
- Server functions: `seedCatalog`, `searchCatalog`, `chat` (streaming SSE route at `/api/chat`), `compareProducts`, cart CRUD, `createScribeToken` (ElevenLabs).
- System prompt stored server-side and injected per request — never sent from client.
- Anonymous session via httpOnly cookie; no auth needed for the demo.

### Out of scope

Real payments, real shipping, user accounts, product reviews, multi-language, image upload search.
